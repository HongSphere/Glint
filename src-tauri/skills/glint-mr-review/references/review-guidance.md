# MR 评审要点与分级标准

## 输出分级定义

- **🔴 高（`high`）**：实质 Bug 或高危缺陷。会导致错误计算结果、数据污染/丢失、空数据返回、并发竞态损坏、接口行为破坏性改变或安全漏洞。
  - 必须给出：确切位置、触发场景与复现条件、具体可执行的代码修复建议。
- **🟠 中（`medium`）**：明确隐患、实现与声明不符、异常/资源处理缺陷、需人工重点确认的风险点。
- **🟡 低/建议（`low`）**：代码健壮性、性能微优化、命名规范、单测缺口、非阻塞代码风格。
- **✅ 已验证无问题的点（`positives`）**：必须列出经核实确认无安全/逻辑风险的关键点（写明核实依据与行内证据）——提升评审公信力，避免“只挑毛病”。

## 跨语言核心审查项（按工程主题）

无论项目基于 Go、Java、Python、Rust、TypeScript/Node 还是其他技术栈，均需重点审视以下通用架构与质量维度：

### 1. 并发控制与锁 (Concurrency & Locking)
- **锁租约（Lease / TTL）**：无论使用 Redis 分布式锁还是进程内互斥锁，租约时间是否必然大于“拿锁后操作”的最坏耗时？
- **防慢操作锁提前过期**：无看门狗/心跳续期机制时，慢操作期间锁过期会导致其他实例重复获取锁，造成“重复处理”或“旧写覆盖新写”；
- **超时与降级策略**：加锁等待超时后是快速失败、保留旧值，还是盲目强行更新？
- **高频事件与去抖**：异步刷新、MQ 消费或数据同步任务是否具备合并与去抖（Debounce/Throttle）机制，防止 N 次并发写触发 N 次全量重刷；
- **线程/协程安全**：共享变量与集合并发读写是否导致 Data Race、死锁或资源争用（如 Go slice/map 并发写 panic、Rust RefCell 借用冲突、Java 共享哈希表等）。

### 2. 状态存储与缓存 (Caching & Storage)
- **Key 构造与序列化一致性**：Key 前缀规范、编解码格式（String vs JSON vs Protobuf vs 二进制编解码）在读写两端是否严格对齐；
- **缓存穿透、击穿与雪崩**：
  - 批量写入缓存时是否加入随机抖动（Jitter），防止集中大面积失效导致雪崩；
  - 遇到缓存未命中或底层刷新失败时，是否有降级兜底逻辑？务必区分“底层读取异常”与“Key 不存在”，严禁因异常而静默返回空数据或脏默认值；
- **共享对象被篡改 (Cache Object Mutation)**：直接将内存缓存/共享状态对象返回给上层调用者时，是否会被调用方修改（In-place mutation）从而污染全局快照（应采用不可变对象或深拷贝防御）。

### 3. 多租户与数据隔离 (Tenancy & Isolation)
- **数据作用域与隔离**：
  - 无论采用 ORM/中间件自动注入拦截（如 MyBatis-Plus `TenantLineInnerInterceptor`、GORM 插件、Django/FastAPI 中间件）还是手写 SQL 过滤：
  - 明确区分「全局共享数据表」与「租户/用户专属数据表」，确认相关表是否有租户标识字段（如 `tenant_id`）；
- **上下文丢失风险**：
  - 显式辨别“HTTP 请求线程（携带完整用户/租户上下文）”与“后台定时任务/异步 MQ 消费（无请求上下文）”的行为差异；
  - 后台任务访问多租户数据时是否显式指定了目标租户，或在加载公共配置时显式安全绕过租户拦截；
- **权限与越权漏洞 (IDOR)**：
  - 对外读写操作是否在根据主键 ID 操作前，二次核验了当前租户/用户的所属权，防止越权篡改他人资源。

### 4. 事务边界与外部一致性 (Transactions & Consistency)
- **长耗时操作脱离事务**：在数据库事务（`@Transactional` / `db.Begin()` / 事务上下文）内严禁包含远程网络调用（如 HTTP 请求、长 RPC、发邮件、第三方鉴权等），防止连接池占满打垮系统；
- **外部副作用的提交时机**：
  - 外部副作用（发送 MQ 消息、触发领域事件、写缓存、调用外部系统）应在数据库事务「确认提交成功后」再行触发（如 Spring `@TransactionalEventListener(AFTER_COMMIT)` 或本地事务表 Outbox 模式）；
  - 严禁在事务回滚后外部副作用已被触发，导致产生幽灵事件与数据不一致；
- **读-改-写并发竞态**：检查校验（读）与更新（写）之间是否存在竞态窗口，必要时采用原子更新语句（`SET num = num - 1 WHERE num >= 1`）、版本号乐观锁或分布式锁兜底。

### 5. 接口契约与向前/向后兼容性 (API Compatibility)
- **对外暴露契约的稳定性**：REST API、gRPC Protobuf、GraphQL 或跨服务 MQ Payload 的变更必须保持向后兼容：
  - 严禁直接删除或重命名已有字段；
  - 新增必填参数必须提供安全默认值；
  - 变更返回值结构（如列表层级、状态枚举值）时，评估旧版客户端/调用方是否会反序列化崩溃；
- **清理与依赖彻底性**：声明废弃或重构的代码，其关联的远程依赖、依赖库引用及配置项是否已彻底清理，避免遗留死代码与无效网络握手。

### 6. 常见语言陷阱与资源防御 (Language Pitfalls)
- **Go**：
  - Goroutine 泄漏（未退出的无缓冲 Channel、未监听 `ctx.Done()`）；
  - 并发读写非并发安全集合（`fatal error: concurrent map writes`）；
  - `defer` 资源释放位于循环体内导致句柄堆积；未处理的错误直接抛弃。
- **Java / Kotlin**：
  - Spring 事务由于类内部自调用导致代理失效；
  - 泛型类型擦除导致 JSON 反序列化成 `LinkedHashMap` 引发运行时 `ClassCastException`；
  - 线程池任务无界队列导致 OOM，线程池未配置优雅关闭。
- **TypeScript / JavaScript**：
  - 异步未捕获异常导致 Node 进程崩溃；未等待的 Promise 竞态；
  - 大整数（超过 `2^53 - 1`）精度丢失（应采用 string 或 BigInt 处理）；
  - 对象浅拷贝解构造成的原型污染或嵌套引用修改。
- **Python**：
  - 函数默认参数为可变对象（如 `def func(a=[])`）导致全局状态串扰；
  - 协程缺少 `await` 导致逻辑被跳过；异常处理过于宽泛（`except Exception: pass`）吞没关键故障。
- **Rust**：
  - 生产主流程中随意使用 `unwrap()` / `expect()` 带来 Panic 风险；
  - `tokio::select!` 中异步分支被提前取消时未保存的状态丢失。

### 7. 变更纯洁性与工程规范
- **杜绝无关夹带改动**：审查是否存在与 MR 标题/意图无关的代码（如针对特定日期的硬编码一次性补偿 Job、个人本地测试配置、大范围无意义的空格格式化等），应要求提交者拆分独立 PR；
- **测试覆盖**：MR 宣称的单测覆盖是否真实存在且能通过；核心脆弱路径（编解码、并发保护、锁超时、事务回滚）是否有自动化测试支撑。
